# 學生操作手冊：用 AI 協作完成一篇研究短報告

這份手冊帶你從零開始，一步一步完成整個練習。每一步都寫了：**要做什麼、要輸入什麼、會看到什麼、怎麼確認做對了**。

- 課堂時間：3 小時（做到第 7 步）
- 課後作業：補充文獻、轉成 APA 格式（各約 1 小時）
- 資料：臺灣高級中等學校校級面板資料（103–114 學年度），學校層級，沒有學生個人資料

## 1. 下載模板與資料（約 10 分鐘）

### 1-1 選擇開始方式

| | 做法 A：直接 clone（**課堂建議**） | 做法 B：Use this template |

| 繳交方式 | 壓縮成 zip | `git push` |
| 適合 | 課堂練習 | 想保留在自己的 GitHub、老師要線上看進度 |

**沒有特別要求的話，選做法 A。**

### 1-2 下載模板

先切換到你想放專案的資料夾，例如桌面：

```powershell
cd ~\Desktop
```

**做法 A**：

```powershell
git clone https://github.com/gemini960114/mri-data-starter
cd mri-data-starter
```

**做法 B**：到 https://github.com/gemini960114/mri-data-starter 按綠色的「**Use this template**」→「Create a new repository」，名稱填例如 `mri-data-group3`，建立後再 clone 你自己的 repo：

```powershell
git clone https://github.com/你的帳號/mri-data-group3
cd mri-data-group3
```

### 1-3 建立環境並下載資料

```powershell
$env:UV_LINK_MODE="copy"
uv sync
uv run python src/get_data.py
```

| 指令 | 做什麼 |
|---|---|
| `$env:UV_LINK_MODE="copy"` | 避免出現跨磁碟的警告（可省略，警告不影響結果；Mac 不用輸入） |
| `uv sync` | 依 `uv.lock` 安裝完全相同版本的 Python 套件，第一次約 30 秒到 1 分鐘 |
| `uv run python src/get_data.py` | 下載資料並核對 SHA-256 |

**會看到**（最後一行）：

```
[OK] hs_school_year.csv 的 SHA-256 正確，和全班使用的資料完全相同。
```

✅ **檢查點**：看到 `[OK]` 才往下。全班的資料完全相同，所以結果不同一定是方法不同。

**下載失敗**：向老師拿 zip 檔，把 `hs_school_year.csv` 放進 `data/` 資料夾，再執行一次 `get_data.py`。

### 2-1 在專案資料夾裡啟動 AI


> 使用其他 AI 程式助理（例如 Claude Code）也可以，一樣要在 `mri-data-starter` 資料夾裡啟動。

### 2-2 輸入第一句

```
你目前要遵守哪些規則？我們現在在 MRI-DATA 的哪個階段？
```

**預期的回答**應該包括：

- 寫作順序是 Methods → Results → Introduction → Discussion → Abstract → Title → Assembly
- **方法凍結前不能計算任何結果**
- 數字都要來自 `results/`、不可以編造文獻
- 目前在 **M 階段**（因為還沒有 `methods-frozen` 標籤）

✅ **檢查點**：AI 有提到這些規則。代表專案裡的 `AGENTS.md` 生效了，它是寫給 AI 看的規則檔。

**AI 答不出這些規則**：通常是開錯資料夾。請確認 Antigravity IDE 開啟的是 `mri-data-starter` 資料夾本身（不是它的上一層），再重新開啟 AI 面板。

## 3. 分組與角色

每組 3–4 人，統計所和教育所混合。開始前先分好角色：

| 角色 | 建議由誰擔任 | 工作 |
|---|---|---|
| **AI 操作員** | 輪流，每個階段換人 | 輸入提示詞、執行指令 |
| **方法把關** | 統計所 | 檢查 AI 寫的方法和程式是否合理 |
| **教育解讀** | 教育所 | 定義研究問題、解讀教育意義、寫研究限制 |
| **數字查核員** | 任一人 | 逐一核對論文裡的數字有沒有對應到結果檔 |

> 為什麼要分角色：避免一個人操作、其他人旁觀。「數字查核員」專門練習「不盲信 AI，要查證」。

## 4. 第 1 步 M：研究方法與凍結（約 40 分鐘）

**這是整個練習最重要的一步。** 目標是：在看到任何結果之前，把研究方法寫清楚並凍結。

> **為什麼要先定方法？** 同一份資料，不同的分析選擇可能得到不同結果。例如 4 個選擇、每個各有 2 種做法，就有 16 種組合。如果看完結果才選，很容易挑到「最好看」的那一種，結論就不可信了。

### 4-1 選題（5 分鐘，不用 AI）

打開 `docs/research_questions.md`，從 **A 或 C** 選一題（B 留給老師示範）：

| 題目 | 研究問題 | 適合 |
|---|---|---|
| **A** | 103→114 學年度，私立高中一年級學生數的下降幅度，是否大於公立高中？ | 想練習「兩組比較」 |
| **C** | 103→114 學年度，專業群科學生占全體學生的比例是上升還是下降？公立和私立的變化是否不同？ | 對技職教育、學程結構有興趣 |

教育解讀組員用一兩句話說明：**為什麼這個問題重要？**

### 4-2 請 AI 協助填寫計畫（20 分鐘）

`analysis_plan.yml`（分析計畫）和 `paper/01_methods.md`（研究方法）clone 下來時就有了，但只是骨架，裡面標 `TODO` 的地方要依你們的題目填寫。

**輸入（選題目 A 的組別）**：

```
我們選擇研究問題 A：103 到 114 學年度，私立高中一年級學生數的下降幅度，是否大於公立高中？
請先讀 AGENTS.md、docs/research_questions.md 和 docs/codebook.md。
你可以查看 data/hs_school_year.csv 的欄位與結構，但不要計算任何結果。

請協助我們：
1. 填寫 analysis_plan.yml 裡的每個 TODO（只能有一個主要假設）
2. 填寫 paper/01_methods.md 裡的 TODO（「資料來源」那段已經寫好，保留不動）

遇到需要選擇的地方（例如要不要排除進修學校、只比較兩個學年度還是看趨勢），
請列出選項和各自的優缺點，讓我們決定，不要直接替我們決定。
```

**輸入（選題目 C 的組別）**：

```
我們選擇研究問題 C：103 到 114 學年度，專業群科學生占全體學生的比例是上升還是下降？公立和私立的變化是否不同？
請先讀 AGENTS.md、docs/research_questions.md 和 docs/codebook.md。
你可以查看 data/hs_school_year.csv 的欄位與結構，但不要計算任何結果。

請協助我們：
1. 填寫 analysis_plan.yml 裡的每個 TODO（只能有一個主要假設）
2. 填寫 paper/01_methods.md 裡的 TODO（「資料來源」那段已經寫好，保留不動）

遇到需要選擇的地方（例如要不要排除進修學校、只比較兩個學年度還是看趨勢），
請列出選項和各自的優缺點，讓我們決定，不要直接替我們決定。
```

**會看到**：AI 先讀檔案、查看資料結構（欄位、列數、學年度），然後**列出幾個需要你們決定的問題**，每題附選項和優缺點。

> ⚠️ 如果 AI 在這一步算出了平均數、變化率或畫了圖，就是違反規則。請直接告訴它：「現在是 M 階段，請不要計算任何結果。」

### 4-3 AI 會問的問題與建議選項

下面是 AI 很可能會問的問題，以及**建議的選項和理由**。建議不是標準答案；你們可以選別的，但**一定要能說出理由**，而且要在看結果之前決定。

#### 題目 A 的常見問題

| AI 會問 | 建議選項 | 理由 |
|---|---|---|
| 分析單位：全國加總比較，還是先算每所學校的變化再比較？ | **每所學校的變化** | 可以做統計檢定；全國加總只有兩個數字，無法檢定。全國加總可以列為探索性分析 |
| 「下降幅度」怎麼定義？ | **變化率或對數變化**：ln(114 年人數 ÷ 103 年人數) | 大學校減的人數一定比較多，用變化率才能比較不同規模的學校 |
| 比較哪幾個學年度？ | **只比較 103 和 114 兩個端點** | 最簡單，和題目「下降多少」直接對應 |
| 中途新設或退場的學校？ | **只納入 103 和 114 學年度都存在的學校**（用 `school_id` 配對） | 每所學校才有起點和終點可比較。限制：退場的學校會被排除，要寫進研究限制 |
| 要排除哪些學校？ | **排除進修學校、特殊教育學校、矯正學校**；兩年中有任一年一年級人數為 0 的也排除 | 這些學校的招生方式和一般高中不同；人數為 0 無法計算變化率 |
| 公立怎麼定義？ | **國立（`public_national`）＋地方公立（`public_local`）合併為公立** | `sector` 有四類，矯正學校已排除 |
| 學校的公私立依哪一年？ | **依 114 學年度** | 少數學校可能改制；說明清楚即可 |
| 主要假設 | **私立學校的平均下降幅度大於公立學校** | 題目本身就有方向 |
| 檢定方法 | **Welch t 檢定**（單尾或雙尾見下一列） | 兩組樣本數和變異數可能不同，Welch 不需要假設變異數相等 |
| 單尾還是雙尾？ | 假設有方向就用**單尾**，並寫出理由；不確定就用**雙尾** | **假設和檢定方式要一致**，這是試跑時漏掉的地方 |

#### 題目 C 的常見問題

| AI 會問 | 建議選項 | 理由 |
|---|---|---|
| 「技職」包含哪些學程？ | **只算專業群科**（`students_vocational`） | 題目問的是專業群科；綜合高中、實用技能學程另有欄位，可以列為探索性分析 |
| 比例怎麼算？ | **專業群科學生數 ÷ 學生總數**（`students_vocational / student_total`） | 學生總數已排除附設國中部 |
| 分析單位：全國或每所學校？ | **每所學校的比例變化**（114 年比例 − 103 年比例） | 可以做統計檢定；全國比例的逐年趨勢可以列為探索性分析 |
| 只有普通科的學校怎麼辦？ | **只納入 103 學年度有專業群科學生的學校** | 沒有專業群科的學校，兩年比例都是 0，會稀釋結果 |
| 比較哪幾個學年度？ | **只比較 103 和 114 兩個端點** | 和題目直接對應 |
| 中途新設或退場的學校？ | **只納入兩個學年度都存在的學校**（用 `school_id` 配對） | 才有起點和終點可比較 |
| 要排除哪些學校？ | **排除進修學校、特殊教育學校、矯正學校、學生數為 0 的學校** | 招生方式不同或無法計算比例 |
| 主要假設 | **公立和私立學校的比例變化有差異**（不預設方向） | 題目問「是否不同」，沒有明確方向，用雙尾 |
| 檢定方法 | **Welch t 檢定（雙尾）**；如果比例變化的分布很偏，可以改用 Mann-Whitney U 檢定 | 要在凍結前決定用哪一個，不能看完結果再選 |

### 4-4 組內檢查（10 分鐘）

AI 填完後，**全組一起讀** `analysis_plan.yml` 和 `paper/01_methods.md`：

- **方法把關**：用的欄位都存在嗎？統計方法適合嗎？假設方向和單尾／雙尾一致嗎？
- **教育解讀**：研究問題寫清楚了嗎？樣本規則合理嗎？

有要修改的地方，直接告訴 AI，例如：

```
請把樣本規則改成：只納入 103 學年度有專業群科學生的學校，並在 Methods 說明理由。其他不要動。
```

接著執行檢查：

```powershell
uv run python src/check_stage.py M
```

**會看到**：

```
【M】Methods
  ✅ analysis_plan.yml 必填欄位都已填寫
  ✅ 計畫用到的 N 個欄位都存在
  ✅ 01_methods.md 已填寫
  ❌ 尚未凍結。確認方法無誤後執行：……
```

除了「尚未凍結」，其他都要是 ✅。常見的 ❌：

| 訊息 | 處理 |
|---|---|
| `未填欄位：['group', 'members']` | 請 AI 填入組別與組員，例如「group 填『第 3 組』，members 填 [王小明, 李小華]」 |
| `計畫用到資料中不存在的欄位` | 請 AI 改成 `docs/codebook.md` 裡真的有的欄位 |
| `01_methods.md 還有 TODO 沒填` | 請 AI 補完 |

### 4-5 凍結前確認清單

**凍結後就不能改**，請逐項確認：

- [ ] `group`、`members` 已填寫
- [ ] 主要假設只有一個
- [ ] 假設有方向的話，有寫出理由，而且和單尾／雙尾一致
- [ ] AI 建議的修改都已經完成
- [ ] 全組都讀過兩個檔案
- [ ] **老師或助教看過**

### 4-6 凍結（5 分鐘）

**老師看過後**，執行：

```powershell
git add -A
git commit -m "凍結研究方法"
git tag methods-frozen
uv run python src/check_stage.py M
```

| 指令 | 做什麼 |
|---|---|
| `git add -A` | 把所有修改加入待存清單 |
| `git commit -m "凍結研究方法"` | 存成一個版本 |
| `git tag methods-frozen` | 在這個版本貼上「方法凍結」的標籤 |

✅ **檢查點**：最後的檢查四項全部 ✅，包括「已凍結（git tag methods-frozen 存在）」。

> **凍結請由你們自己執行，不要請 AI 代勞。** AI 也被規定不能替你們打標籤，因為凍結是研究者的決定。

## 5. 第 2 步 R：分析與結果（約 40 分鐘）

**目標**：完全照凍結的計畫執行分析，把結果寫下來，每個數字都查得到來源。

### 5-1 請 AI 寫分析程式並執行（15 分鐘）

**輸入**：

```
方法已經凍結。請依照 analysis_plan.yml 寫 src/analysis.py 並執行
（用 uv run python src/analysis.py）。
表格存成 CSV、圖存成 PNG，都放在 results/，檔名照 analysis_plan.yml 的 outputs。

不要修改 analysis_plan.yml 和 paper/01_methods.md。
如果發現計畫行不通，請先停下來告訴我們原因和建議做法；
我們同意後，先寫進 deviations.md 再執行。
```

**會看到**：AI 寫好程式並執行，`results/` 裡出現 CSV 和 PNG，AI 會簡短描述結果。

### 5-2 確認程式照計畫執行（5 分鐘）

**方法把關**組員輸入：

```
請逐段說明 src/analysis.py 在做什麼，並指出每一段對應 analysis_plan.yml 的哪一項。
另外列出計畫沒有寫、由程式自行決定的細節。
```

確認每一段都對得上計畫。AI 列出的「計畫沒寫、程式自行決定的細節」（例如排名同分怎麼處理），討論時可以提到。

### 5-3 請 AI 寫結果段落（15 分鐘）

**輸入**：

```
請根據 results/ 裡的檔案寫 paper/02_results.md：
1. 先寫主要分析：樣本數、統計量、p 值，並依凍結的判斷標準說明主要假設是否得到支持
2. 再寫描述性結果
3. 最後寫探索性分析，標題或第一句要明確標示「探索性」
只描述結果，不要解讀原因。
數值位數依 APA：統計量取小數第 3 位、p 值取小數第 3 位（小於 0.001 寫 p < 0.001）。
每個數字後面都要標註來源檔，例如：（results/table1.csv）。
寫完後執行 uv run python src/check_stage.py R 給我看。
```

### 5-4 數字查核（5 分鐘）

```powershell
uv run python src/check_stage.py R
```

**會看到**類似：

```
【R】Results
  ✅ results/ 有 3 個 CSV 結果檔
  ✅ 02_results.md 已填寫
  ✅ 02_results.md 的 N 個數字都能在 results/ 的 CSV 中找到
```

**全部 ✅ 還不夠。** 檢查工具只確認數字「有出現」在結果檔裡，不確認對應到正確的位置，例如排名「13」可能剛好在別的欄位也出現。**數字查核員**要打開 `results/` 的 CSV（可以用 Excel 開），**至少抽查 5 個數字**，確認對應到正確的列和欄。

出現 ⚠️「找不到來源的數字」時：

| 情況 | 處理 |
|---|---|
| 真的找不到 | 請 AI 刪除或改正 |
| 其實有，只是換算方式不同（例如 0.3 寫成 30%） | 確認無誤即可 |
| 是衍生數字（例如「減少了多少人」） | 請 AI 在程式中計算並存成結果檔；這個表不在計畫裡，所以**先寫進 `deviations.md`** |

### 5-5 如果需要改計畫

例如發現某個欄位全是 0、樣本太少。AI 會先停下來說明。你們同意後，請它先記錄：

```
我們同意這個修改。請先在 deviations.md 新增一列（原本計畫、實際做法、原因、是不是看到結果之後才改），再照新做法執行。
```

> 改計畫不是壞事，**誠實記錄**才是重點。分享時要說明一筆計畫變更。

## 6. 第 3 步 I：前言（約 10 分鐘）

**目標**：說明為什麼研究這個問題。由**教育解讀**組員主導。

**輸入**：

```
請根據 paper/01_methods.md 和 paper/02_results.md 填寫 paper/03_intro.md：
這個問題為什麼重要、背景是什麼、本研究要回答什麼。

研究問題必須和 Methods 一致，不能新增，也不能因為看到結果就改變問題的寫法。
前言不要透露研究結果。
需要引用文獻的地方，如果沒有可查證的 URL 或 DOI，請寫「TODO：需補文獻」，不要編造。
數字該用阿拉伯數字就用阿拉伯數字，不要為了避開檢查改寫。
寫完後執行 uv run python src/check_stage.py I 給我看。
```

**檢查**：

- 研究問題和 Methods **一字不差**嗎？
- 有沒有提前說出結果，例如「本研究發現……」？
- 有沒有沒查證過的具體數字或說法？有的話改成不帶數字的說法，或標「TODO：需補文獻」。

**會看到**：`⚠️ 03_intro.md 有 N 處「TODO：需補文獻」` 是正常的，課後作業再補。

> **為什麼前言放在結果之後寫？** 先寫前言，很容易寫出一個「預期結果」，然後不自覺地往那個方向詮釋。

---

## 7. 第 4 步 D：討論（約 15 分鐘）

**目標**：解讀結果的意義，誠實說明限制。

**輸入**：

```
請根據 paper/01_methods.md、02_results.md、03_intro.md 填寫 paper/04_discussion.md：

1. 先討論主要分析：主要假設是否得到支持，說明可能的解釋；解釋要寫成「可能」，不能寫成已證實的原因。
2. 再討論探索性分析：必須明確說明這是探索性結果，不能據此宣稱主要假設成立或改變結論。
3. 研究限制，至少包括：資料是學校層級彙總、不能推論到個別學生；一年級學生數不等於招生人數；只比較兩個學年度；樣本規則造成的限制（例如退場學校被排除）。

請區分「關聯」和「因果」，不要寫成「A 造成 B」。
討論中的數字必須是 02_results.md 已經出現的數字。
寫完後執行 uv run python src/check_stage.py D 給我看。
```

**檢查**：

| 項目 | 要確認的 |
|---|---|
| 關聯 vs 因果 | 沒有「造成」「導致」「使得」這類因果字眼 |
| 主要 vs 探索性 | 探索性結果沒有被拿來改寫結論 |
| 數字 | `check_stage.py D` 顯示數字都能在 02_results.md 中找到 |
| 限制 | 具體、和你們的方法有關，不是空泛的套話 |

> **主要分析不顯著，但探索性分析顯著，怎麼辦？** 結論仍然依照主要分析。探索性結果可以當成「之後值得檢驗的新假設」，要在新的研究中事先寫進計畫再檢驗。

## 8. 第 5–6 步 A＋T：摘要與標題（約 10 分鐘）

**輸入**（把組別和組員換成你們的）：

```
請根據 paper/01 到 04 填寫：
1. paper/05_abstract.md：200 字以內，包含目的、資料、方法、主要發現、結論。主要發現必須是主要分析的結果；探索性結果如果要提，必須標明是探索性。
2. paper/00_title.md：中文與英文標題；組別寫「第 3 組」，組員寫「王小明、李小華、陳大同」。

摘要中的每個數字都必須出現在 02_results.md。標題要反映主要結果，不要誇大，也不要用探索性結果當標題。
結果不顯著時，寫「未發現顯著差異」，不要寫「兩者沒有差異」。
寫完後執行 uv run python src/check_stage.py A T 給我看。
```

**檢查**：

- 摘要不超過 200 字（中文一般不計空白）
- 標題反映的是主要分析，不是探索性結果
- 不顯著的結果沒有被寫成「證明沒有差異」

## 9. 第 7 步 Assembly：組裝與存檔（約 5 分鐘）

寫作順序是 M → R → I → D → A → T，但讀者看到的順序是：標題 → 摘要 → 前言 → 方法 → 結果 → 討論 → 參考文獻。`assemble.py` 會依閱讀順序組裝。

```powershell
uv run python src/assemble.py
uv run python src/check_stage.py
git add -A
git commit -m "完成論文初稿"
```

**會看到**：

- `assemble.py`：`[OK] 已組裝 paper.md（7 個部分）`，可能附上「還有 N 個 TODO」（文獻待補，正常）
- `check_stage.py`：**沒有 ❌**；⚠️ 文獻待補是正常的

打開 `paper.md`，從頭到尾讀一遍你們的論文。

## 10. 分享準備（每組 2 分鐘）

準備說明三件事：

1. **研究問題和主要發現**（一句話）
2. **一筆計畫變更**（`deviations.md`）：改了什麼、為什麼改？沒有改的話，說說遇到什麼困難
3. **一個 AI 犯的錯**：例如用錯欄位、偷算結果、數字對不上、寫了沒查證的說法、為了通過檢查改寫數字

> 試跑時 AI 犯過的錯，可以參考：把數字改寫成國字來避開檢查、寫入沒查證的「可能包含重讀生」、假設有方向卻預設雙尾檢定。

## 13. 常見問題

| 問題 | 原因 | 處理 |
|---|---|---|
| `uv sync` 出現 `Failed to hardlink files` | uv 的快取和專案不在同一個磁碟 | 可忽略；或先輸入 `$env:UV_LINK_MODE="copy"` |
| AI 答不出專案規則 | 開錯資料夾 | 用「檔案 → 開啟資料夾」開啟 `mri-data-starter` 本身，再重新開啟 AI 面板 |
| AI 在 M 階段就算出結果 | 違反規則 | 告訴 AI「現在是 M 階段，請不要計算任何結果」，刪掉它產生的結果檔 |
| 不確定凍結是 commit 還是 tag | 兩個都要 | commit 存內容，tag 標記「這一版是凍結版」 |
| 凍結後才發現想改方法 | — | **不能刪標籤重來**。照原計畫執行，在討論中說明；真的必須改，先寫進 `deviations.md` |
| 組別、組員忘了在凍結前填 | — | 不屬於方法，寫在 `paper/00_title.md` 就好 |
| `check_stage.py` 顯示「凍結後被修改」 | 凍結後改了計畫或 Methods | 還原：`git checkout methods-frozen -- analysis_plan.yml paper/01_methods.md`，要改的寫進 `deviations.md` |
| 圖上中文變成方框 | 電腦沒有中文字型（常見於 Linux） | 請 AI 改用英文標籤 |
| AI 說的數字和結果檔對不上 | AI 抄錯或心算 | 以結果檔為準，請 AI 改正 |
| AI 想用 skill 或外掛 | — | 課堂上不使用；`AGENTS.md` 的規則優先 |

## 14. 附錄：常用指令

### 檢查進度

```powershell
uv run python src/check_stage.py        # 所有階段
uv run python src/check_stage.py M      # 只看某一階段：M R I D A T X
```

| 符號 | 意思 |
|---|---|
| ✅ | 通過 |
| ⚠️ | 請人工確認（例如文獻待補、找不到來源的數字） |
| ❌ | 未完成或違反規則 |

### git

| 指令 | 用途 |
|---|---|
| `git status` | 看有哪些檔案被修改 |
| `git add -A` | 把所有修改加入待存清單 |

| `git log --oneline` | 看版本紀錄 |
| `git tag --list` | 看有哪些標籤 |
| `git diff methods-frozen -- analysis_plan.yml` | 看凍結後計畫有沒有被改 |

# 課後作業一　補充文獻（約 1 小時）

**目標**：把論文中所有「TODO：需補文獻」補上**可查證、而且有人讀過**的來源。補文獻的同時也是在查核說法：找不到支持的說法，就要改寫或刪除。

**最重要的規則：沒有人親自讀過的文獻，不可以引用。**

| 步驟 | 誰做 | 做什麼 | 產出 |
|---|---|---|---|
| 8-1 搜尋計畫 | AI | 找出需要來源的說法，列出搜尋關鍵字 | `refs/search_plan.md` |
| 8-2 搜尋 | **你們** | 到資料庫與官方網站搜尋，把結果存進 `refs/` | `refs/found_R1.md`…… |
| 8-3 驗證與篩選 | AI | 查證文獻是否存在、判斷是否支持原句，產生決定表 | `refs/screening.md`、`refs/decisions.md` |
| 8-4 閱讀與決定 | **你們** | 打開來源閱讀，填寫決定表 | 填好的 `refs/decisions.md` |
| 8-5 修改論文 | AI | 依你們的決定插入引用、改寫句子 | 更新的章節與參考文獻 |
| 8-6 全文校正 | AI | 檢查引用、說法與數字是否前後一致 | `refs/final_check.md` |

開始前先存檔：`git add -A && git commit -m "開始補文獻"`

---

## 8-1　產生搜尋計畫（AI）

```
# 產生文獻搜尋計畫（不要自己找文獻）

請找出 paper/ 中所有「TODO：需補文獻」的地方，以及其他需要來源但沒有標註的背景事實，產生搜尋計畫，存成 refs/search_plan.md。

不要自己搜尋或提供任何文獻，由我們自己去搜尋。不要修改 paper/ 的任何檔案。

每一個需要文獻的地方，請列出：
1. 編號與位置：例如 R1，paper/03_intro.md 第 1 段
2. 需要支持的說法：原文引用那一句
3. 說法類型：
   - 「事實或統計」（例如出生數、政策年份）→ 應查政府或官方資料
   - 「學術論點」（例如人口移動對學校的影響）→ 應查學術文獻
4. 什麼樣的文獻才算支持：一句話說明
5. 搜尋關鍵字：
   - 學術論點：Elicit 用的英文問句 2–3 個（Elicit 用問句搜尋效果最好），以及中文關鍵字 2–3 組（給華藝線上圖書館、Google Scholar 用）
   - 事實或統計：建議查詢的官方網站或資料名稱，以及搜尋關鍵字
6. 篩選條件：例如優先選臺灣的研究、近 15 年、經過同儕審查

如果某句說法看起來本身就不精確，請一併指出。
```

## 8-2　搜尋（你們自己做，不用 AI）

1. 打開 `refs/search_plan.md`，依關鍵字搜尋：
   - **學術論點**：[Elicit](https://elicit.com/)、[華藝線上圖書館](https://www.airitilibrary.com/)、[Google Scholar](https://scholar.google.com/)
   - **事實或統計**：內政部、教育部、[全國法規資料庫](https://law.moj.gov.tw/) 等官方網站
   - Elicit 以英文學術文獻為主，臺灣的官方統計與中文文獻要另外查。
2. 每個編號帶回 **3–5 篇**候選文獻：
   - 能匯出的（例如 Elicit 的 CSV 或 BibTeX）存成 `refs/elicit_R1.csv`
   - 不能匯出的，把標題、作者、年份、期刊、DOI 或網址、摘要貼進 `refs/found_R1.md`
   - 官方資料沒有 DOI，要記下發布機關、資料或法規名稱、網址與**查詢日期**
3. 至少讀過摘要，才能放進候選清單。

> **不要請 AI 替你們搜尋。** 試跑時 AI 搜尋的結果大多可靠，但 AI 最常見的錯不是捏造文獻，而是「文獻存在，但其實不支持那句話」。判斷文獻能不能支持論點，是研究者的核心能力。

## 8-3　驗證與篩選（AI）

```
# 驗證並篩選 refs/ 裡的文獻（先不要修改論文）

請驗證我們放在 refs/ 裡的候選文獻，再篩選。

規則：
- 不要修改 paper/ 的任何檔案，也不要修改我們的搜尋結果檔。
- 不可以新增 refs/ 裡沒有的文獻。
- 判斷只能根據你實際讀到的內容；沒讀到的標成「未確認」，不可以推測。

步驟 1：驗證文獻是否存在
- 有 DOI 的：到 Crossref（https://api.crossref.org/works/〔DOI〕）查詢，比對標題、作者、年份、期刊、卷期頁碼。
- 有網址的：打開網址，確認頁面存在、內容和描述相符。
- 無法連網或打不開的，標成「未確認，請學生自行開啟」。

步驟 2：判斷是否支持原句，存成 refs/screening.md，每篇一列：
| 編號 | 文獻 | 存在與否（✅ 已驗證／⚠️ 未確認／❌ 查無此文獻或資訊不符） | 支持程度（✅ 直接支持／⚠️ 部分支持／❌ 不支持） | 理由（引用讀到的原文或摘要） |

步驟 3：產生決定表 refs/decisions.md 給我們填寫，每個編號一列：
| 編號 | 原句位置 | 建議做法 | 我們的決定 | 讀過的人 | 備註 |
「建議做法」只能是：引用（寫出哪一篇）／改寫（附改寫後的句子）／改成推測（改成「本研究推測……」）／刪除，並說明理由。
「我們的決定」「讀過的人」兩欄留白，由我們填寫。
```

## 8-4　閱讀與決定（你們自己做）

1. 打開 `refs/screening.md`，**親自打開**每一筆建議引用的網址或 DOI，至少讀摘要；政府資料和法規要讀到相關段落。
2. 在 `refs/decisions.md` 填寫「我們的決定」（引用／改寫／改成推測／刪除）和「讀過的人」，存檔。
3. **沒人讀過的文獻不可以引用**；只讀過摘要的，備註寫「只讀摘要」。

## 8-5　依決定修改論文（AI）

```
# 依 refs/decisions.md 修改論文

先檢查 refs/decisions.md 是否存在，而且「我們的決定」與「讀過的人」兩欄有填寫。
如果檔案不存在或兩欄是空白，請停下來，提醒我們先完成 8-3 與 8-4，不要自己建立或填寫決定表。

確認後，只依「我們的決定」欄修改：
1. 引用：把對應的「TODO：需補文獻」換成 APA 第 7 版的文中引用，例如（郭義汶、吳清山，2017）或（Smith & Lee, 2019）
2. 改寫、改成推測、刪除：照我們的決定修改該句，不要動其他句子
3. 把引用的文獻加進 paper/06_references.md，依 APA 第 7 版排列；中文文獻在前、英文在後
4. 官方網頁與法規要寫出機關、年份、名稱、網址與擷取日期

規則：
- 只能引用「讀過的人」欄有填寫的文獻
- 不可以修改 analysis_plan.yml、paper/01_methods.md、paper/02_results.md、results/
- 不可以新增或改變任何數字
- 「我們的決定」欄沒填的編號，維持「TODO：需補文獻」

完成後列出每一處修改（檔案、原句、新句），然後執行：
uv run python src/assemble.py
uv run python src/check_stage.py
```

## 8-6　全文校正（AI）

```
# 全文校正（先列出問題，不要修改）

請檢查 paper.md 全文，只列出問題，先不要修改，存成 refs/final_check.md。

檢查項目：
1. 引用與參考文獻對應：每個文中引用都在 06_references.md 裡；06_references.md 的每一筆都有在文中被引用；作者與年份兩邊一致
2. 參考文獻格式：是否符合 APA 第 7 版
3. 背景事實：前言與討論中不是來自 results/ 的說法，是否都有引用或已改寫成推測
4. 前後一致：研究問題、主要假設、數字，在標題、摘要、前言、方法、結果、討論中是否相同
5. 關聯與因果：有沒有把關聯寫成因果
6. 方法未被修改：執行 git diff methods-frozen -- analysis_plan.yml paper/01_methods.md，應該沒有輸出

回報格式：
| 編號 | 位置 | 問題 | 建議改法 | 類別（1–6） |

最後執行 uv run python src/check_stage.py，附上結果。我們看過後，會告訴你哪些要改。
```

## 完成後

```bash
git add -A
git commit -m "完成文獻補充"
git tag paper-final
```

`paper-final` 標記「這一版是定稿內容」，下一個作業（APA 排版）會用它來確認排版沒有改到內容。

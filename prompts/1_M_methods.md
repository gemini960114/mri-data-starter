# 第 1 步　M：研究方法（約 40 分鐘）

**目標**：在看到任何結果之前，把研究方法寫清楚並凍結。

## 1-1 選題（5 分鐘，不用 AI）

組內討論，從 `docs/research_questions.md` 的 A、B、C 選一題。教育所組員說明：為什麼這個問題重要？

## 1-2 請 AI 協助寫計畫（20 分鐘）

`analysis_plan.yml` 和 `paper/01_methods.md` clone 下來時就有了，但只是骨架，裡面標 `TODO` 的地方要依照你們的題目填寫。

把下面這段複製給 AI，**把 `[ ]` 裡的內容換成你們的選擇**：

```
我們選擇研究問題 [A／B／C]：[把研究問題貼上來]。
請先讀 AGENTS.md、docs/research_questions.md 和 docs/codebook.md。
你可以查看 data/hs_school_year.csv 的欄位與結構，但不要計算任何結果。

請協助我們：
1. 填寫 analysis_plan.yml 裡的每個 TODO（只能有一個主要假設）
2. 填寫 paper/01_methods.md 裡的 TODO（「資料來源」那段已經寫好，保留不動）

遇到需要選擇的地方（例如要不要排除進修學校、只比較兩個學年度還是看趨勢），
請列出選項和各自的優缺點，讓我們決定，不要直接替我們決定。
```

## 1-3 組內檢查（10 分鐘）

- **方法把關**（統計所）：用的欄位都存在嗎？統計方法適合這個問題嗎？
- **教育解讀**（教育所）：樣本規則合理嗎？研究問題寫清楚了嗎？
- 有地方要改，就繼續請 AI 修改。

執行檢查：

```bash
uv run python src/check_stage.py M
```

除了「尚未凍結」，其他項目都要是 ✅。

## 1-4 凍結（5 分鐘）

凍結前最後確認（凍結後就不能改）：

- [ ] `group`、`members` 已填寫
- [ ] 主要假設只有一個；如果有方向（例如「越大越…」），有寫出理由，而且和單尾／雙尾檢定一致
- [ ] AI 建議的修改都已經完成
- [ ] 全組都讀過 `analysis_plan.yml` 和 `paper/01_methods.md`

**請老師看過計畫後**再執行：

```bash
git add -A
git commit -m "凍結研究方法"
git tag methods-frozen
```

再執行一次 `uv run python src/check_stage.py M`，全部 ✅ 就可以進入第 2 步。

> **為什麼要凍結？** 看到結果後，人很難不受影響，例如「這個方法不顯著，換一個試試」。先凍結方法，就能避免這種情況；git 標籤會記錄凍結的時間點。
